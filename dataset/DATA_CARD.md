# TMO selection dataset — data card

Per-image data for learning which tone-mapping operator (TMO) to use on an HDR image. It covers 992 HDR images
and 17 operators, with each output scored by TMQI. It was produced by the TMO benchmark in this repository and
regenerated by `python export_dataset.py`.

## Files

| file | rows | what it holds |
|---|---|---|
| `tmo_selection_dataset.csv` | 992 (one per image) | identifiers, 151 HDR features, the 10-bin histogram, TMQI of all 17 TMOs, labels |
| `scores_long.csv` | 16,864 (992 × 17) | every image × operator pair: TMQI Q / S / N, FSITM, FSITM_TMQI, TMQI-II Q2 / S2 / N2, and u / sigma |
| `feature_dictionary.csv` | 174 | each feature column: group, published source, what it measures |
| `selector_oof_predictions.csv` | 992 | our selector's out-of-fold pick per image, for comparison only |
| `hdr_features_original22.csv` | 992 | the project's earlier hand-made feature set (21 columns), the reference set in the report |

## Histogram definition

1. Take the linear HDR (Radiance `.hdr`) and compute luminance Y = 0.2126 R + 0.7152 G + 0.0722 B.
2. Floor zero pixels at the smallest positive luminance, then take log10.
3. Bin into 10 equal-width bins between that image's minimum and maximum log10 luminance.

The histogram describes **the HDR input only**. It is computed before any operator runs, so it cannot leak
the label. `python export_dataset.py --bins N` regenerates it with N bins.

The earlier `histogram_data.csv` worked differently: its label equalled argmax(Bin_6 … Bin_10) on all 634
rows, which is why logistic regression reached about 98% on it. These bins are not built from the label.

## How the scores were produced

**Images.**
- 1000 deduplicated HDR images: 628 from HDR-Real and 372 from HDR-Synth (Liu et al., CVPR 2020).
- Deduplication used md5 hashes plus a thumbnail-similarity check.
- Each image was resized so its long side is 512 px.
- 992 images were scored successfully by all 17 operators. The other 8 had a failed or degenerate
  output (all black or all white) for at least one operator; see `results/failures.csv`.

**Operators.**
- Every operator ran with its library defaults. There was no per-image tuning.
- The 13 classical operators ran through luminance-hdr-cli 2.6.1.1 (Ubuntu 24.04 package) in Docker. Eight of them were run with
  `--postgamma 2.2`, because they output linear luminance (see `experiments/reinhard_check/FINDINGS.md`).
- The three learned operators ran with their authors' released weights.

**TMQI.**
- Computed with the `tmqi-revised` Python port of the authors' MATLAB code.
- Each output is scored against the original linear HDR at the output's resolution.
- For catmo, the reference is centre-cropped the way catmo crops its input.

## Suggested use and pitfalls

- **Evaluate on TMQI, not only on accuracy.** Many images have near-ties:
  - On 44% of images, the runner-up is within 0.005 TMQI of the best.
  - On 67%, it is within 0.01.
  - So exact-label accuracy understates a selector's real quality. Report the mean TMQI of the picked
    operator (from the `TMQI_<op>` columns) as well, alongside the floor and the ceiling:
    - the best single operator, always-catmo: 0.9357;
    - the oracle: 0.9629.
- **Use only out-of-fold predictions.** The `cv_fold` column reproduces our split.
- **Features and labels.**
  - Use the 151 features and/or the histogram as inputs.
  - Never use the `TMQI_*`, `best_*`, `second_*` or `selector_oof_predictions.csv` columns as inputs.
  - `width`, `height` and `source` identify the source collection. Leave them out, or test with and without
    them.
- **Reference results** (5-fold CV, seed 1234):
  - our structured LightGBM on the 151 features reaches a mean TMQI of 0.9596, with 65.2% exact accuracy;
  - a random-forest classifier on `hdr_features_original22.csv` reaches about 0.9554, with 52.2% exact
    accuracy.
